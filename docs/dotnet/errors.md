# Error reference (.NET)

**Implements** [`specifications/04-error-model.md`](../../specifications/04-error-model.md)
(`ERR-001`…`ERR-037`) and [Appendix B — error catalogue](../../specifications/appendix-b-error-catalogue.md),
adapted to .NET's `BastionVaultException`. Every SDK call that can fail raises exactly this one
type, carrying a stable `Code`, a category, a `Message`, a `Hint`, and whether retrying could ever
help.

This is a reference document, not a guide, so it does not follow the `DOC-010` task order. The
table below the marker is generated by `tools/error-catalogue` straight from Appendix B
(`DOC-002`, `DOC-007`: every hint is reproduced verbatim, because it is the same text the
generator already emits into `ErrorCatalogData.g.cs`) and regenerating it is part of the same
`python tools/error-catalogue/generate.py` step that keeps the three SDKs' catalogues in sync
(DR-0018 D-M11-11). Only the region between the two HTML comments is generated; everything else on
this page, including this paragraph, is hand-written and survives a regeneration untouched.

## Reading an error

Every `BastionVaultException` prints, by default, as one line (`ERR-002`):

```text
BV-AUTHZ-001: The token does not have permission for this path (or the token is invalid, expired or revoked). — Check the token's policies grant the capability on `Details.path` (`Sys.CapabilitiesSelf`); verify the token with `Auth.Token.LookupSelf`; if the credential is namespace-scoped set `Namespace`; a `token_bound_cidrs` or `bound_source_ips` rule may exclude this client. [HTTP 403 GET secret/data/app/db] (server: "permission denied")
```

Read it left to right:

1. **Code** — `BV-AUTHZ-001`. Stable, never localised, identical across all three SDKs. Look it up
   in the table below.
2. **Message** — the SDK's own description of what went wrong, independent of what the server said.
3. **Hint**, after the em-dash — what to check, including anything the SDK could add from the
   request's own context.
4. **`[HTTP <status> <METHOD> <path>]`** — the request as sent, present whenever the failure has a
   status code. `Path` is redacted for token/lease lookups (`ERR-003`) and is otherwise the logical
   path, not the wire URL.
5. **`(server: "...")`** — the raw server text, when the SDK captured one, so you can grep an audit
   log for it.

Then:

- **`e.Retryable`** — `false` means fix configuration or policy and try again; `true` means the SDK
  already retried `e.Attempts` times before giving up, and retrying again immediately will not help
  either.
- **`e.Details`** — structured extras keyed by name (`setting`, `path`, `cas_expected`,
  `retry_after_secs` and others the catalogue documents per code).
- **`e.Cause`** — the underlying runtime exception for transport/TLS failures, when there is one.
- **`e.Category`** — one of the `ErrorCategory` values, the same grouping the table below uses.

<!-- docs:sample errors/reading-an-error -->
```csharp
try
{
    await client.Kv.V2.ReadSecretAsync("app/db", mount: "secret");
}
catch (BastionVaultException e)
{
    // e.ToString() is exactly ERR-002's one-line form; never build your own from
    // the parts, and never parse it back apart — switch on e.Code instead.
    Console.Error.WriteLine(e);

    Console.WriteLine($"code:       {e.Code} ({e.Category})");
    Console.WriteLine($"retryable:  {e.Retryable}, attempts: {e.Attempts}");
    Console.WriteLine($"server:     {e.ServerMessage}");
    Console.WriteLine($"request:    HTTP {e.StatusCode} {e.Method} {e.Path}");
    throw;
}
```

### What goes over the wire

The 403 above is the server's response to this request; the SDK's recognition rules (the second
generated table below) turn its plain-text body into `BV-AUTHZ-001`:

```http
GET /v1/secret/data/app/db HTTP/1.1
Host: vault.example.com:8200
X-BastionVault-Token: s.FAKEtoken
Accept: application/json
```

```json
{
  "errors": ["permission denied"]
}
```
